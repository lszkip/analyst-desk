ANALYST DESK — ORIGINAL ANNUAL-REPORT CORPUS
Revision 3 — prepared 10 November 2026. Base: PR #7 merged, main d387b86.

PURPOSE
The next retrieval milestone needs original annual-report text and tables.
Our existing /ask service uses structured SEC financial facts. This update
prepares one original 10-K HTML document per company/fiscal year, with its
source and reporting dates. Target: 15 companies x FY2023–FY2025 = 45 reports.

This package does NOT yet extract passages, index vectors, rerank results or
change /ask. Keeping complete HTML preserves tables for the next parser step;
it is not yet the required table-aware passage extraction. AWS, Terraform and
Lambda remain outside this submission step.

REVISION 3: EQUIVALENT INLINE REPORT DATES
The next live failure was DIS FY2023: conflicting inline filing identity.
Inspection of the original SEC HTML reproduced the issue. The filing includes
DocumentPeriodEndDate twice in the same context: hidden 9/30/2023 with the
XBRL date-month-day-year transform, and visible September 30, 2023 with the
English month-name transform. Both mean 2023-09-30.

The shared identity reader now compares canonical report dates after applying
supported, namespace-qualified date formats. Numeric dates need a recognised
format declaration; there is no locale guessing. Truly conflicting dates,
different contexts, invalid dates and unsupported transforms still fail.
Original HTML bytes and fingerprints are unchanged. This is a narrow subset
of XBRL date transformations, not a complete XBRL implementation.

Eight new regression tests cover equivalent dates through preparation and
verification, different dates, different contexts, unsupported/missing formats,
invalid dates, namespace aliases and scope, supported registry versions, and
compatibility with explicit fiscal-year evidence. Real Disney FY2023 and
Salesforce FY2025 HTML also passed identity validation in the build workspace.
This is not proof of full 45-report coverage on the laptop.

WHAT GETS SAVED
  data/filings/objects/<sha256>.html
    Exact original HTML bytes. Tables and inline tags remain intact.
  data/filings/receipts/<ticker>_<year>_<accession>.json
    Per-document metadata enabling resumable preparation.
  data/filings/manifest.json
    Catalogue for the later parser: company, sector, fiscal year, period,
    filing date, accession, original URL, HTML hash/size, source-cache hashes,
    inline identity, acquisition method and preparation timestamp. A new HTTP
    download records downloaded_at; reuse of an earlier fiscal-year source
    records downloaded_at as null because its download time is not known.

The manifest is published only when every requested document succeeds and
the financial snapshots still agree with the original plan. On failure the
previous manifest remains intact; completed receipts are reused on retry.
Earlier HTML objects remain available, including after an explicit refresh.

SCOPE AND LIMITATIONS
- The policy is one evidenced original 10-K per company/year. Partial 10-K/A
  amendments do not replace the narrative report. Financial lookup still
  applies its own existing latest-value/amendment policy. Later research must
  disclose when narrative and numerical evidence come from different filings.
- Ambiguous or missing original filings stop preparation. No guessed periods.
- The HTML validator supports UTF-8 inline-XBRL 10-Ks with consistent cover
  identity. Unsupported historical formats or inconsistent labels stop with
  an error for review; real-corpus testing may reveal a format to add.
- The metadata checks consistency and provenance. It does not independently
  audit SEC accounting data, detect every document injection or verify every
  numerical statement in a report. Retrieved text must remain untrusted data.
- SEC HTTP requests are sequential, capped at roughly 3.33/second, with a
  declared contact, 30-second socket timeout, 25 MiB response limit and no
  redirects. A 403/429 should be investigated or retried later, not bypassed.
- Use one preparation process at a time. Concurrent writers are unsupported.
- --refresh reprepares selected reports. For documents already used as
  fiscal-year evidence, it reuses the exact verified data/raw snapshot; for
  other documents it downloads again. It does not refresh data/raw. Do not
  run it routinely; changed-source failures deserve review.
- --as-of YYYY-MM-DD selects only filings published by that date. Verification
  must use the same cutoff. Future retrieval must apply its own cutoff filter.
