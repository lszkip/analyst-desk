WHAT THE THREE TOOLS DO

list_companies()
  Lists 15 configured companies, aliases and five exact metric definitions.
  Configuration does not guarantee that every fact is present in the cache.

list_annual_filings(ticker, as_of=null, limit=20)
  Reads cached 10-K and 10-K/A filing metadata. Newest first; limit 1 to 100;
  optional YYYY-MM-DD filing-date cutoff. Includes source URLs and a cache hash.
  It returns reporting dates, not fiscal years guessed from those dates.
  No matching filings gives an empty successful list; a missing/bad cache is
  a structured error. Original fiscal-year evidence is checked when present.

get_annual_financial_fact(ticker, metric, year, as_of=null)
  Uses the existing verified lookup. Fiscal year is required; parent net income,
  consolidated net income and pretax income remain different measures.
  The result retains the shared lookup payload exactly, including source URLs
  and fingerprints, so the existing replay guard can verify the same evidence.
  not_found, conflict and unsupported_period remain explicit and have no amount.

All tools advertise read-only annotations and have input and output schemas.
Bad schema arguments return an MCP tool error; data/identity/cutoff failures
return structured status/code/message results. The process stays running.
There are no cache downloads, API-key requirements, model calls or write tools.
The server does not load .env. Data paths are fixed by operator startup settings,
not accepted as tool arguments. Tool annotations describe behaviour; the
read-only Docker filesystem and mount enforce the file restrictions.

3. START BOTH SERVICES

  docker compose config --quiet
  docker compose up --build --detach --wait --wait-timeout 90
  docker compose ps

Expected: BOTH api and edgar are healthy. The first MCP build can take a few
minutes. The wait timeout applies after building, during service startup.

The API remains at http://127.0.0.1:8000/docs.
EDGAR MCP uses http://127.0.0.1:8001/mcp.
Its liveness check is http://127.0.0.1:8001/health and returns:

  {"status":"ok","service":"edgar-mcp"}

The MCP endpoint is a protocol endpoint, not a Swagger page. Test it with the
client below. Both services use your Linux user/group IDs and a read-only data/
mount. The edgar container receives no OpenRouter key. Only localhost ports are
published; this local checkpoint has no public authentication or internet hosting.

4. CALL THE REAL MCP SERVER OVER HTTP

  docker compose exec edgar python check_edgar_mcp.py --url http://edgar:8001/mcp --ticker MSFT --metric net_income --year 2025

Expected:
  Discovered MCP tools: get_annual_financial_fact, list_annual_filings, list_companies
  Configured companies: 15
  JSON result with status ok, ticker MSFT, fiscal_year 2025 and source evidence.

This client runs inside the edgar container and connects to the running server
over HTTP using Compose's edgar hostname. It performs protocol discovery and a
real cached lookup. It uses no model credits and makes no SEC download.

Also check the development transport:

  docker compose exec -T edgar python check_edgar_mcp.py --stdio --ticker MSFT --metric net_income --year 2025

The client starts a separate short-lived server subprocess and exchanges MCP
messages through its input/output pipes. Expect the same fact and fingerprints.
The HTTP service continues running independently.

TROUBLESHOOTING

- Permission error: check that ANALYST_UID and ANALYST_GID still match your WSL
  account, as in the previous Docker checkpoint. Do not use root or chmod 777.
- data_file_missing: the MCP server is alive but the requested cache is absent.
  Prepare the cache on the host using the existing downloader; this server never
  downloads or repairs files itself.
- Connection error: check docker compose ps and docker compose logs --tail=80 edgar.
- Port 8001 allocated: stop the older MCP development server using that port.
- A browser displays a protocol error at /mcp: use /health for a browser check
  and check_edgar_mcp.py for actual MCP calls.
- /health succeeds but a fact fails: liveness does not prove cache coverage.
- This server intentionally accepts only localhost and the edgar service host
  plus the actual listening interface; unrelated Host/Origin headers are rejected.
