5. START QDRANT

docker compose config --quiet
docker compose up -d qdrant retrieval-gateway
docker compose ps qdrant retrieval-gateway
curl --noproxy '*' --fail --show-error --retry 10 --retry-connrefused \
  --retry-delay 1 --retry-max-time 30 --connect-timeout 3 --max-time 5 \
  http://127.0.0.1:6333/healthz

The gateway must show 127.0.0.1:6333->6333/tcp and 127.0.0.1:8002->8002/tcp.
Qdrant itself intentionally has no host-published port. A container attached only
to an internal network cannot publish a host port. The fixed-route gateway is
the only retrieval service attached to a normal bridge; Qdrant and filings-kb
remain internal-only. The gateway has no source/model mounts or credential env.
It forwards Qdrant authentication headers unchanged and preserves MCP streaming.
Its healthy status proves gateway liveness; /healthz above checks Qdrant itself.
If the health request fails immediately after startup, check the logs below.

Qdrant is reached only through 127.0.0.1:6333 on the host. Its files persist under
data/qdrant_storage and data/qdrant_snapshots. Keep those folders on the WSL
Linux filesystem. The service runs as your configured ANALYST_UID/GID.
Give it a moment to start before indexing. On failure, capture:

docker compose logs --no-color --tail=100 qdrant retrieval-gateway > ./LSOutput/QdrantOut.txt 2>&1

6. BUILD THE INDEX FOR THE COMPLETE PREPARED PASSAGE MANIFEST

python prepare_filing_index.py 2>&1 | tee ./LSOutput/IndexOut.txt

There is no --all switch: the index includes every company/year already in the
verified passage manifest. The command first replay-verifies those inputs.
For your corpus, expected coverage is 45 company-years and 16,235 total source
passages (10,901 text + 5,334 tables). Search-window count is different because
long passages and tables have multiple searchable windows. The 239 unassigned
passages remain included with item=null; no Item is guessed.

Initial CPU indexing may take a substantial time. Progress is printed every
64 windows. You can interrupt it and run the same command again: completed,
verified embedding batches are reused. A failed build keeps the previously
published index manifest. Do not use --refresh unless inputs/settings changed.

7. VERIFY THE COMPLETE INDEX

python prepare_filing_index.py --verify-only 2>&1 | tee ./LSOutput/IndexVerifyOut.txt

This is read-only. It replays source extraction, checks corpus/model fingerprints,
checks Qdrant point counts, every vector and every point's metadata against the
saved embedding batches. Expected: status ok and coverage company_years 45.

If original passages/models change deliberately, prepare them first and then:

python prepare_filing_index.py --refresh
docker compose restart filings-kb edgar

New index generations preserve old Qdrant collections. This update has no
automatic deletion/garbage collection. Do not delete collections by hand while
a retrieval service is using them.

9. START AND TEST BOTH MCP SERVERS

docker compose up -d --build edgar filings-kb retrieval-gateway
docker compose ps
python check_filings_kb.py 2>&1 | tee ./LSOutput/MCPRetrievalOut.txt

The first KB readiness check loads the models/index and verifies the vectors;
startup can take longer than subsequent searches. The KB health check uses /ready.
The KB container cannot download models: it has an internal network and offline
model settings. It receives only the read-only Qdrant key, not the administrator
or OpenRouter key. The smoke check also confirms that this key cannot write.

EDGAR now has four tools: list_companies, list_annual_filings,
get_annual_financial_fact and get_section. get_section returns paginated complete
source passages/tables by company, fiscal year and Item. Very large tables can
be paged by the KB get_table_rows tool without losing cell IDs/merged spans.

The KB has five tools: plan_search, search_filings, get_passage,
get_table_rows and get_coverage. These are tools within one server. This milestone
therefore supplies TWO domain MCP servers; python-sandbox/research-portal remain.

10. EXPORT THE 40-QUESTION SOURCE REVIEW PACK

python export_retrieval_review.py 2>&1 | tee ./LSOutput/ReviewExportOut.txt

Outputs LSOutput/RetrievalReview.zip. It contains the 40 questions and all saved
source passages in each question's explicit scope, not rankings from the search
engine. It excludes secrets and models. Upload it to continue relevance labelling.
Nothing is automatically marked relevant, reviewed or passed.

After source review, save reviewed labels as retrieval_labels.jsonl. Each line
needs: id, request, gold_passage_ids, gold_source_sha256 (ID-to-source-hash map),
label_status="reviewed", reviewer, rationale, and
label_scope="all_relevant_passages_reviewed". Judge all relevant passages within
the explicit scope. A single known-answer hit does not establish Recall@5.

python evaluate_filing_retrieval.py retrieval_labels.jsonl \
  2>&1 | tee ./LSOutput/RetrievalEvaluationOut.txt

The evaluator runs BM25, dense, hybrid, and hybrid+reranker on the same cases,
keeps labels out of requests, counts failed runs as zero recall, and records
median/p95 query latency. It writes LSOutput/RetrievalEvaluation.json.
It requires 40 reviewed queries and reports before/after adding the reranker.
The initial PROJECT target is Recall@5 >= 0.70 with no reranker regression; the
capstone brief itself does not prescribe a numeric retrieval threshold. Report
the actual result; do not adjust a held-out threshold after viewing results.
--allow-drafts permits provisional inspection but cannot produce a passing report.

ARCHITECTURE / LIMITS

- BM25 uses rank-bm25. Dense retrieval uses real 384-dimensional BGE vectors in
  Qdrant. RRF merges unique parent-passage ranks (k=60). MiniLM cross-encoder
  scores rerank candidate windows; parent hits retain stable passage IDs.
- Search views repeat available table headings/header rows and compact nonempty
  cells. Layout blanks and spans remain fully present in original table objects
  and cell-ID links; the search text is not an authoritative financial table.
- Token windows cover long content instead of silently embedding just its start.
  Queries and reranker pairs have explicit token bounds; limits fail clearly.
- This local deployment binds only loopback ports and uses a private Docker
  network for retrieval. Only a fixed-route gateway has a second normal bridge;
  Qdrant and the KB stay internal-only. The gateway image is pinned by digest.
  A remote/cloud deployment needs TLS and its own review.
- Search ranking is not proof of truth or an answer. The quant/compliance stages
  must still check numbers and claims before the final note can be published.
- Full-system held-out evaluation, FinanceBench, 12 risk-change company-years,
  30 human judge labels and 40 attacks are separate tracked work. Unit-test
  counts and these 40 unlabelled retrieval questions do not satisfy them.
