HOW AN ANNUAL PERIOD IS CHOSEN

1. Load the company's SEC identity from companies.json.
2. Join annual facts to filing metadata using their accession number.
3. Use records whose filing fiscal-year label matches the requested year and
   whose end date matches that filing's reportDate. This avoids mistaking an
   older comparative figure for the filing's current year.
4. Require a full-year duration of 350–380 days. This covers ordinary calendar
   years and 52/53-week years without writing a calendar formula per company.
5. If more than one annual period matches, return conflict; do not guess.
6. Select the requested measure for the exact start/end dates, using the latest
   matching annual filing in the snapshot (subject to an optional as-of cutoff).
7. Return source links and hashes of both input snapshots.

The fiscal-year label is not assumed to equal the calendar year of the end date.
The accepted input range is 1900–2100, but actual availability depends on the
cached SEC records. Passing a year does not create data for it.

SUPPORTED MEASURES AND LIMITATIONS

revenue:
    RevenueFromContractWithCustomerExcludingAssessedTax, Revenues or
    SalesRevenueNet. Latest matching filing date is considered across tags;
    disagreement on that date produces conflict.

operating_income:
    OperatingIncomeLoss.

net_income:
    NetIncomeLoss (net income/loss attributable to the parent).
    ProfitLoss, which includes the noncontrolling-interest portion, is not
    silently treated as the same measure.

This version handles supported US-GAAP USD facts in 10-K and 10-K/A filings.
It does not yet handle custom company tags, IFRS/20-F, quarterly data, segments,
derived measures or unusual short/long transition years. Choosing a familiar
tag is not a substitute for independently checking its accounting meaning.

Status meanings:
    ok                  A supported value and reporting period were selected.
    not_found           No supported matching period or measure in this cache.
    conflict            Available matching records disagree; no value selected.
    unsupported_period  Only a nonstandard/shorter period could be established.
    error               A required local file is missing, invalid or inconsistent.

not_found does not assert that the company's filing contains no such information.
It states that this lookup could not find it under its supported definitions.

An as-of example:

    python financial_data.py MSFT net_income 2025 --as-of 2025-12-31

This filters by SEC filing date within the downloaded snapshot. It is not a
reconstruction of every byte the SEC website served on that historical date.

CACHE AND REFRESH NOTES

The default command reuses snapshots. To deliberately replace them:

    python download_company_facts.py MSFT GOOGL --refresh

Requests are spaced by at least 0.3 seconds in this process (about 3.3/second).
Use one downloader process at a time; this limit is not coordinated across
processes or other clients sharing your connection. Each response has a
25 MiB size limit and a 30-second timeout. Do not commit .env or contact details.

Each file is replaced atomically, but the entire collection of files is not one
atomic transaction. If a refresh fails midway, facts and filing history can be
from different downloads. Relevant inconsistencies cause a lookup error; rerun
the refresh before treating the cache as a new complete snapshot.

Hashes identify exact local bytes. They help reproducibility; they do not prove
that a financial figure is correct or independently authenticate SEC content.
