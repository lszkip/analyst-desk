ANALYST DESK — BROADCOM AND IBM: DISTINCT FINANCIAL MEASURES
Prepared: 9 November 2026 (Australia/Sydney)

REVISION: MISSING-DATA RESPONSE FIX

The live Broadcom parent-income request returned HTTP 502 with the log message
'The draft did not account for the tool results.' The model selected a
nonfinancial answer kind after a lookup. The output guardrail correctly rejected
it, but the API should have returned a checked explanation of the missing data.

When every lookup returns not_found, conflict or unsupported_period, Python now
builds the status explanation directly. It uses the same output guardrail to
replay the lookup and check the complete evidence against the local snapshots.
There is no second model request for this case, no financial claim, and no
automatic switch to another measure. Tampered evidence still returns HTTP 502.

If any result is ok, the model still proposes claims and every successful result
must match its evidence exactly. Mixed found/missing batches retain that check.
This change does not catch a failed guardrail and turn it into a successful reply.

If you already installed the previous eleven-file version, only main.py,
test_api.py and this instruction file have changed. Copy these three replacement
files beside your existing main.py. Restart Uvicorn, run the 133 offline tests,
then repeat live checks C and D below. No SEC cache refresh is needed.

WHY THIS STEP IS NEEDED

Your Salesforce repair passed 103 tests and produced 131 successful lookups out
of the original 135. The remaining four requests are:
  Broadcom FY2025: net income attributable to the parent.
  IBM FY2023, FY2024 and FY2025: GAAP operating income.

Our cached data contains related figures, but their accounting definitions are
different. This update makes those figures available under separate names.
It does not change the definition of an existing question to improve a score.

Broadcom's ProfitLoss concept reports consolidated net income: the result for
the whole group, including any share belonging to noncontrolling owners.
Our existing NetIncomeLoss lookup asks for the share belonging to the parent.
Missing noncontrolling-interest data does not establish that its value is zero.

IBM's report calls its adjusted operating earnings non-GAAP. That is different
from our supported GAAP operating-income concept. Its GAAP income from
continuing operations before income taxes is available and can be requested
separately. We do not call this figure operating income or calculate a proxy.

The same rules apply to every configured company; there are no Broadcom/IBM
branches in the Python lookup and no hardcoded financial amounts.

METRIC CONTRACTS

revenue
  Supported annual revenue concepts, under the existing selection policy.
operating_income
  OperatingIncomeLoss: reported GAAP operating profit/loss. No non-GAAP, EBIT,
  pretax or inferred revenue-minus-expenses fallback.
net_income
  NetIncomeLoss: after-tax profit/loss attributable to the parent.
net_income_consolidated
  ProfitLoss: after-tax profit/loss for the group including noncontrolling owners.
pretax_income
  IncomeLossFromContinuingOperationsBeforeIncomeTaxesExtraordinaryItemsNoncontrollingInterest:
  GAAP pretax income from continuing operations, including equity-method results
  and before allocation to noncontrolling owners. A similarly named concept that
  excludes equity-method results is deliberately not treated as an alias.

Reported values remain integer USD, with exact annual dates and filing links.
Latest matching annual filings can update earlier comparative figures. as_of
limits filing dates. The Salesforce fiscal-year evidence repair remains active.

VALIDATION AND LIMITS

Prepared and tested in a separate Linux Python 3.12.14 workspace, not your WSL
laptop. The latest delivered API/data files were combined with this update.
All 126 offline tests passed. Real SEC snapshots and original income statements
were used for source checks; no live OpenRouter call was made during preparation.
The local SDK tests simulate the model, so your four live checks remain useful.

The guardrail replays evidence against the local lookup. It is not a separate
accounting audit. Newly supported concepts use the same shared period logic,
unit validation, conflict handling, source hashes and output checks.

The request wording check is intentionally limited: the new measures need an
explicit phrase such as 'consolidated net income', 'pretax income', or 'income
from continuing operations before income taxes'. Adjusted/non-GAAP wording
blocks financial lookups. Compound comparisons involving both GAAP and non-GAAP
figures should be split into separate questions. This is not a complete
company/measure/negation parser, and complete question coverage still needs
the capstone's labelled evaluations.

The app still has a six-lookup maximum and two model calls maximum. It does not
yet calculate margins, growth or differences, retrieve quarters or forecasts,
or answer arbitrary narrative filing questions. Those remain later work.
