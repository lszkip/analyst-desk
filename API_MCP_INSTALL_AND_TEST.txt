ANALYST DESK: CONNECT /ask TO EDGAR MCP
Prepared 10 November 2026 (Australia/Sydney)
Starting checkpoint: main 50516b9, merged EDGAR MCP PR #6.

PURPOSE
The API can now retrieve financial facts through the running EDGAR MCP server.
Compose sets EDGAR_MCP_URL=http://edgar:8001/mcp for the api service and waits
for edgar to become healthy before starting api.

Request path:
  Browser -> FastAPI /ask -> model proposes lookup arguments
  -> existing request guards -> HTTP MCP -> edgar -> saved SEC facts
  -> API verifies returned evidence against its own read-only cache
  -> model proposes claims -> final guardrail -> Python renders the answer.

The model does not choose the MCP endpoint, discover extra tools, or receive
server-provided prompts. No OpenRouter key is forwarded to EDGAR. The API still
needs the same SEC cache mount because it verifies remote evidence locally.
This verification reuses the deterministic financial lookup; it is not an
independent accounting audit of the underlying data or selection algorithm.

The existing two-model-call / six-lookup limit remains. Every MCP batch has a
30-second deadline, with shorter initialization and per-call timeouts. There is
no automatic local retrieval fallback if MCP fails. The original direct/local
mode remains available when EDGAR_MCP_URL is unset, including for the existing
133-test baseline. The Compose deployment explicitly selects MCP.

This is the API-to-MCP connection checkpoint before LangGraph orchestration.
It does not implement multi-agent research, retrieval/reranking, memory,
approval-gated publishing, or cloud deployment.

4. VERIFY THE LIVE /ask PATH
This step uses the existing OpenRouter key and can consume API credits.
Open http://127.0.0.1:8000/docs, expand POST /ask, select Try it out and submit:

  {
    "question": "What were Microsoft's and Google's annual net incomes in fiscal year 2025?"
  }

Expected: HTTP 200, evidence for both companies, guardrail status passed and:

  "lookup_backend": "edgar_mcp"

The backend field identifies the configured route. For a financial request,
the evidence and passed guardrail confirm the successful result. Definition
or clarification replies also identify the configured route but make no
financial MCP call.

Do not compare live values with the invented numbers in test fixtures. Actual
figures, periods and filing dates come from your existing local SEC snapshots.

5. CHECK THAT MCP FAILURE IS VISIBLE
Stop only the EDGAR service:

  docker compose stop edgar

Submit the same financial question again in /docs. Expected: HTTP 503 with
detail.code = edgar_mcp_unavailable. No financial answer should be returned.
This verifies that the API does not silently retrieve an answer locally.
The initial model request can still consume credits before MCP is contacted.

Restart EDGAR even if the preceding check did not behave as expected:

  docker compose up --detach --wait --wait-timeout 90 edgar
  docker compose ps

Submit the same question again. Expected: HTTP 200 and lookup_backend edgar_mcp.

If the error is financial_data_unavailable, inspect/prepare the SEC cache on
the host. If it is output_guardrail_blocked, the draft or evidence failed
verification; do not disable the guardrail to force an answer. Both services
must see the same complete data directory and readable original documents.
