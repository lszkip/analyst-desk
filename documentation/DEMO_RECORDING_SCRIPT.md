# Analyst Desk demonstration and backup recording script

**Status:** recording plan, not a completed recording. Target length is approximately 8–10 minutes, excluding any clearly identified wait. Use a new run name, retain the actual startup/result reports and show an existing failed check honestly if one is discussed. Do not display credentials, private watchlist entries, `.env` or database contents.

## Before recording

Start the prepared project with `python start_analyst_desk.py`. Confirm the returned startup report and service health. Unlock the UI off camera with its separate token. The demonstration makes paid model calls only after the operator accepts the displayed limits. Have the historical S25/S26 artifacts and the final evaluation report available, clearly labeled as saved evidence.

## Evidence to retain

Keep the recording, its date, startup report, run ID, source/configuration identifiers, old/new review hashes, observed stale-decision response and final publication or failure state. Exclude tokens and private records. Label any fast-forward or replay of historical material. A recording script, offline fixture or screenshot is not a completed live resume, stale-approval or clean-install demonstration.

For a process-resume demonstration, stop and restart the application at a pending gate and show the same saved run afterwards. The approval capability is intentionally not persisted; a restart can require review again. Never kill a process during publication merely to manufacture a recovery scenario.
