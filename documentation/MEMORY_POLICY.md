# Analyst Desk memory policy

Analyst Desk uses the installed LangGraph `SqliteStore` (a `BaseStore`) for durable owner-scoped memory. This is separate from the per-run LangGraph checkpointer and evidence journal. The trusted authenticated application binds the owner; a request or model cannot choose another owner. SQLite is local, with database permissions `0600`; it is not encrypted storage or protection from a compromised local account.

| Saved material | When saved | Who can read it | Correction and deletion |
|---|---|---|---|
| Analyst preferences | Explicit operator action; allowlisted detail, presentation and risk-focus values | Owner; bounded model context contains these values | Correct or delete against the current content hash |
| Coverage history | After a checked note is confirmed published | Owner; prior-note scope may enter context | Delete the associated note; publish a correction for changed scope. This means prior request coverage, not complete filing coverage |
| Past notes and citations | Post-publication hook checks exact approval/publication hash, current sentence receipts, eligible sources and reproduced rendering | Owner; model context contains at most three relevant note summaries, hashes and source links | Published snapshots are immutable. Delete by hash or publish a separate corrected note. Deleting a note also deletes its coverage row |
| Private watchlist labels and annotations | Explicit operator action only | Owner through local authenticated CRUD; never a model or MCP tool | Correct/delete by current content hash |
| Conditional lessons | Drafted from recorded development failures; never silently learned from held-out cases | Owner; only exact-hash human-approved, relevant lessons enter specialist context | Approve/reject with a reason; rejection history persists. Changing a lesson creates a new proposal requiring new review |

**Context and factual boundaries.** Preferences cannot contain free-form instructions. Note memory is a previously published snapshot, not current truth and not a substitute for retrieving and verifying current evidence. Context is bounded (default 6,000 characters, at most three matching notes); omitted entries are marked as truncated. A follow-up reports added, missing or changed source records and links to the prior note and SEC citations. It explicitly does not infer a business change, filing-wide risk change or source truth from that inventory difference. Model-visible memory must be frozen in the run configuration/plan approval; changed memory requires a new run or fresh review, rather than silently altering an approved task.

**Private-data boundary.** Private watchlists are excluded structurally from context. Before every external model and tool dispatch, `guard_external` checks normalized payload strings and keys against private labels and annotations, even with memory disabled. An exact public ticker label can be exempted only when it appears in the trusted reviewed request's ticker scope; membership and annotations are never exported. A source asking for the watchlist cannot read the local CRUD interface. Literal private-value checks also cover case, compatibility characters and zero-width formatting. They do not claim to detect arbitrary encoding, paraphrases, all fragments, or already-public information; errors omit private values. The database, private UI responses and backups must never be uploaded as evaluation evidence.

**Retention and human review.** Each owner/category is limited to 500 entries; no implicit expiry or eviction changes historical evidence. The authenticated local application performs corrections and deletion; deletion removes active records, not external backups. Historical note receipts establish provenance and the recorded review, not infallible semantic accuracy. Lesson review is an authenticated human action, not a model-emitted boolean. Both approval and rejection require the exact proposal hash and a reason. The frozen playbook includes exact approved lessons and a manifest hash; any relevant approval/content change invalidates it. Freeze before held-out evaluation, retrieve only matching tags/roles, and do not tune from held-out results without reclassifying them as development.

**Evidence.** `test_workflow_memory.py` checks persistence, owner isolation, correction/deletion, unpublished-note rejection, source-instruction rejection, private-value dispatch blocks, the public-ticker exception and bounded contexts. `deterministic_memory_comparison` runs identical request/source inputs with memory off and on, reporting the visible context and source-linked follow-up with zero model calls. It is an offline behavior comparison, not a measured real-model quality improvement. Lesson tests cover drafts, exact-hash decisions, retained rejection reasons, relevant retrieval and freeze invalidation. A real-model memory-on/off comparison and before/after held-out playbook scores require separately recorded runs.
