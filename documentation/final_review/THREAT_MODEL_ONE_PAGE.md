# Threat model

**Assets and trust.** Protect model/service credentials, operator review capabilities, private watchlists, source integrity, the publication record and the host. Filing passages, retrieved tables and model outputs are untrusted data. The authenticated operator, application code and local source/database administrator are trusted. A compromised local account, malicious administrator or direct database tampering is outside the tested boundary.

**Source to model.** Tool outputs mark source content as untrusted. Source identifiers and hashes establish which bytes were read; they do not establish truth. S31 showed a writer adopting an instruction to invent a renewal guarantee; the actual S32 critic approved the same claim despite reading the full source. No publication occurred in that isolated diagnostic. S33's narrow detector makes recognized explicit source-to-agent instructions ineligible as evidence. It scans full original passages and table strings, preserves originals, and rechecks support during rendering, approval, preparation and publication. Model approval cannot override this check.

**Model to tools.** Typed arguments, exact approved company/year scope and role-specific tool lists constrain dispatch. Models cannot choose arbitrary endpoints, file paths or operator credentials. Tool results must match requested identities before entering the evidence registry. The Python sandbox uses a separate child process with syntax, environment, time/memory/output and Linux kernel restrictions; actual tests exercise network, file and process denial. These probes do not establish universal sandbox resistance.

**Draft to publication.** Plan/note decisions bind to exact hashes. Editing invalidates earlier approval; current evidence is rechecked before publication. The publication capability stays in the trusted operator process. Losing it returns work to review. Human approval is not an MCP tool. Scoped service tokens, loopback host checks, origin restrictions and scrubbed errors separate browser, model and operator authority. Private watchlists are owner-scoped and excluded from model context, with a literal dispatch guard as additional protection.

**Known gaps.** The source detector can miss indirect, encoded, multilingual and cross-passage instructions or ordinary false assertions. It can block benign training material quoting executable attacks and adjacent useful facts. Literal advice/private-data checks can miss paraphrases or encodings. Operator judgment, credential theft and dependency compromise require separate controls. Custom guards and a local event journal are used; Llama Guard, Prompt Guard and LangSmith are not deployed.

**Evidence boundary.** S33's 236 passing software tests and the new tool-contract report establish specific enforcement behavior, not an attack-success rate. Fair model-based defenses-off/on and clean false-block results are a separate deliverable and must retain errors and unrun cases. S37/S39 establish local deployment/tool readiness; they do not establish semantic security. The 24 human-attested support labels do not validate security classification; historical judge agreement is ineligible (18 binary pairs, negative kappa). No cloud-security or external-alert-delivery claim is made.
